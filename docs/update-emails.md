# アップデートのメール通知

## 配信サービス

Brevo の Email API を使います。無料枠は 1 日 300 通（2026-10-18 に公式料金ページを確認）。
Azuki は余裕を持って **直近 24 時間で 290 回の送信試行** に制限します。テスト・失敗・結果不明もカウントします。
API の日次リセット時刻に依存しません。他アプリで同じ Brevo アカウントを使う場合は、さらに上限を減らしてください。
https://help.brevo.com/hc/en-us/articles/208589409-About-Brevo-s-pricing-plans

## 有効にする前の設定

本番では EMAIL_ENABLED=true とし、APIキーはWorker Secretに保存します。配信は管理画面で明示的に開始したものだけが対象です。

1. Brevo アカウントで送信ドメインを認証し、案内された DNS レコード（DKIM 等）を登録します。
2. 送信元 support@volta.jp を認証します。返信・問い合わせもこのアドレスです。
3. Worker Secret に API キーを登録します。ブラウザ向け VITE_ 環境変数には入れないでください。

   ```sh
   npx wrangler secret put BREVO_API_KEY --config wrangler.api.jsonc
   ```

4. wrangler.api.jsonc の EMAIL_API_URL に **本番 Worker の公開 URL + /api/email/unsubscribe** を設定します。
   ログイン不要でアクセスできる HTTPS の URL が必要です。クエリや末尾の / は付けません。
5. D1 migration 0014_update_emails.sql を適用し、Worker と Web を公開します。
   EMAIL_ENABLED を true にして、5 分ごとの Cron Trigger が登録されていることを確認します。
   GitHub Actions によるデプロイでも同じ設定を保持してください。
6. `/admin/emails` を管理者アカウントで開き、下書きを保存 → 自分宛てにテスト送信。
   次の Cron 実行まで最大 5 分程度かかります。件名・表示・返信先・送信ドメイン・迷惑メール判定を実際のメールで確認します。
7. 受信設定を有効にしたテスト用アカウントへの配信で、メール末尾の停止リンクを確認します。
   GET では確認画面のみ、POST で停止します。List-Unsubscribe-Post にも対応しています。
8. 一斉配信は「配信内容を確認」→「全受信登録者への配信を開始」の明示的な操作で開始します。

本番の管理画面は https://azuki.mame-app.com/admin/emails です。添付されたVolta Technologiesのロゴをメール用PNGに変換し、フッターに使用しています。

## 対象ユーザー

- 確認済みGoogleメールアドレスを持ち、通知を停止していないユーザーが対象です。
- ライブラリまたは通知設定の取得時に、未登録の受信設定をオンで作成します。既存のオン・オフ設定は上書きしません。
- 初期設定は `updates-default-v1`、明示的な受信操作は `updates-v1` と記録し、初期設定を同意取得として記録しません。
- 既存の D1 users テーブルにはメールアドレスがないため、未登録の既存ユーザーは次回のログイン・ライブラリ表示時に登録します。Firebaseの全件取り込みは行いません。
- 未確認メールは登録せず、別アカウントの同一メールアドレスも重複登録しません。
- 配信開始時点で対象者を固定し、送信直前にも停止・メールアドレス・同意時刻を確認します。
  送信処理がすでに始まった 1 通を取り消すことはできません。
- アドレスの重複登録は UNIQUE 制約で防ぎます。送信は 1 人ずつ。CC/BCC は使用しません。
- 保存先は D1 email_subscribers。退会・情報削除の受付時には、このテーブルと email_deliveries の個人情報も削除対象です。
  停止の記録を消すと再配信防止に影響するため、削除対応時は対象ユーザーの待機ジョブを先に中止してください。

## キューと障害対応

- 5 分おきに最大 10 件。1 件ずつ送るため Worker のサブリクエスト数を抑えています。
- D1 の原子的な UPDATE RETURNING で宛先と枠を確保し、並行実行・二重クリックでも同じ送信を取得しません。
- 同じ下書きのテスト送信は 1 回だけ。一斉配信の開始も冪等です。内容を修正する場合は新しい下書きを作成します。
- `accepted` は Brevo が API で受け付けた状態です。到着・開封の確認ではありません。
- 4xx は `failed`、ネットワークエラー・タイムアウト・5xx・受付 ID のない結果は `unknown`。
- 実行中に Worker が落ちた場合は 10 分経過後に `unknown` にします。**自動再送はしません**。
  Brevo の送信ログで確認してください。結果不明のキャンペーンを丸ごと作り直すと重複配信になるため避けます。
- `cancelled` は未送信分を止めます。受付済みのメールは取り消せません。
- 上限を使い切ったキューは、過去の送信試行が 24 時間を過ぎると再開します。
- 緊急停止は EMAIL_ENABLED=false に変更して Worker をデプロイします。
- Brevo 側のバウンス・ブロックリストと送信ログを確認してください。この実装では到着・開封・バウンスの Webhook 同期は行っていません。

## ローカル検証

```sh
npx vitest run tests/email.test.ts tests/email-ui.test.tsx tests/routes.test.tsx tests/core.test.ts
npx tsc --noEmit
npm run build
```

API テストは SQLite とモック送信器を使用し、外部にメールを送りません。
ローカル API を利用する場合は `npm run db:local`、`npm run dev:api` を起動し、VITE_API_BASE_URL を空にして Vite proxy を使います。
本番 API を参照している既存の .env.local のままでは、本番に API を反映するまで通知設定は取得できません。

## メールのデザイン・編集

`shared/emailTemplate.ts` が配信メールと画面プレビューの共通テンプレートです。メールクライアント向けにテーブルとインラインCSSを使用します。ロゴは public/email-logo.png を本番Webと一緒に公開してください。メールでは https://azuki.mame-app.com/email-logo.png を参照するため、最初のテスト送信前にWeb側も反映してください。画像をブロックするメールアプリでも azuki の文字は表示されます。

件名と本文は自由入力です。本文ツールバーの「太字」（選択範囲を ** で囲む）と「画像を挿入」（公開HTTPS画像URL）に対応します。画像は独立した行の `![説明](https://example.com/image.png)` として保存し、プレビュー・配信で同じ表示にします。画像本体のアップロードやDB保存はせず、URLのみを本文に保存します。画像URLは送信後も公開を維持してください。空行は段落、改行は改行として保持し、HTTP(S)のURLをリンクにします。入力HTMLは実行されず文字として表示します。本文内のURLと配信停止リンクはプレビューでは操作せず、実際のテストメールで確認してください。

ローカルの `/dev/email-preview` では、ログインやAPI接続なしで編集とPC・スマホ幅の表示を確認できます。このページに保存・送信機能はなく、本番ビルドにはこのルートはありません。実際の下書き保存・テスト配信は `/admin/emails` を使用します。
