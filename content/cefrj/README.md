# CEFR-J standard books

Source: **CEFR-J Wordlist Version 1.6**, compiled by Yukio Tono, Tokyo University of Foreign Studies. Retrieved October 2026 from https://www.cefr-j.org/download.html#cefrj_wordlist (download: https://www.cefr-j.org/data/CEFRJ_wordlist_ver1.6.zip).

Original XLSX SHA-256: `e41033a12f92983012a0a6b201d4f1f860b7ba3de700c2c3b89660ea21a390e1`.

`SOURCE-README.txt` preserves the workbook README, including its custom usage terms: educational, research and commercial use is permitted without charge with appropriate acknowledgement; modified lists must also cite the source. This is **not a CC0 dataset**. CEFR-J's general contact page separately discusses commercial permissions; no individual permission request or endorsement has been obtained. The implementation includes attribution and makes no claim of supervision or certification.

`source-entries.json` contains the ALL worksheet's headword, part of speech and CEFR level, in worksheet order, enriched with Japanese reference meanings from EJDict. Japanese meanings are not part of CEFR-J. EJDict revision: `9663055d59a8cb1a35078a71db7a09ff39305828`, https://github.com/kujirahand/EJDict, CC0-1.0. Dictionary aliases are resolved with case-sensitive matching first. `meaning-overrides.tsv` supplies Azuki-authored missing meanings and corrections; `headword|pos` overrides a particular part of speech. The reference definitions may contain multiple parts of speech and are not shipped directly as study prompts.

`editorial/a-levels.json`, `b1.json`, `b2.json`, and `b2-tail.json` are the build inputs for all 7,801 entries. Azuki used AI-assisted editorial work to choose one primary meaning per source entry, optional additional meanings of the same part of speech, and a contextual English example for the primary sense. Existing Azuki examples were reused where appropriate and reviewed for part-of-speech mismatches. These senses and examples are Azuki additions, not official CEFR-J translations, sense rankings, or examples. This is not a claim of expert linguistic certification. Source keys and original order are retained. Where the original part-of-speech label is unsuitable for the selected natural usage, `usagePos` and a visible `usageNote` disclose the difference.

The build rejects missing or duplicate entries, empty translations/examples, and duplicate additional meanings. `meaning` is the card prompt; `otherMeanings` and the contextual example appear in expanded word details. Japanese-to-English card backs show only English and its example. Additional meanings are searchable.

Run `npm run content:cefrj` from the repository root to rebuild the catalog and JSON assets. This uses checked-in inputs and needs no network or spreadsheet dependency. Split each level at `ceil(count / 2)` without changing its order; retain distinct parts of speech. A1: 583/583, A2: 706/705, B1: 1223/1222, B2: 1390/1389 (7,801 total entries, not unique spellings). The split is not a subdivision of CEFR difficulty.

These read-only books are static Pages assets, fetched on demand and cached in memory. The catalog is shared by the client and Worker. They are available from the personal/public libraries and `/shared/azuki-cefrj-a1-1-v1` etc. They do not create per-user D1 copies, so user quotas and the 500-word JSON import limit remain unchanged. The JSON fork action copies the entire selected book’s primary meanings/examples into a private personal book. Forks count toward personal quotas and preserve server-verified source attribution; additional meanings and usage notes remain in the standard book. Ordinary reading/study does not copy the book. Reports are recorded in the existing D1 reports table; both the Worker and web app must be deployed for this to work. Moderation of standard content requires a source update/deployment rather than a D1 visibility update. Standard reading itself requires no migration; JSON forks require migrations `0010_json_forks.sql` and `0011_full_book_forks.sql` and the matching Worker release.

Assets have content hashes to prevent stale caches. Old generated assets can be removed when no catalog references them. Keep source/meaning changes and generated catalog/assets together. `npm test` verifies counts, source order, paging beyond 500, search, abort handling, report access and the unchanged user import cap.
